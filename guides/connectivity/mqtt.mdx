---
title: "Use the MQTT Client Plugin in Visual Components"
description: "Connect Visual Components to an MQTT broker to publish and subscribe simulation signals, enabling real-time IoT integration and data exchange."
---

The MQTT Client plugin lets you connect a Visual Components simulation to any MQTT broker. Once connected, you can map simulation signals to MQTT topics — publishing values when signals change and updating simulation signals when messages arrive on subscribed topics. This is useful for IoT dashboards, digital twin scenarios, and integrating with external systems that speak MQTT.

## Prerequisites

- Visual Components 4.4 or higher with the MQTT Client plugin installed
- An MQTT broker reachable from your machine (e.g., Mosquitto, HiveMQ, or a cloud broker)
- Basic familiarity with MQTT concepts: broker, topic, publish, subscribe

## Connect to a broker

<Steps>
  <Step title="Open the MQTT Client panel">
    In Visual Components, go to the **Connectivity** tab in the ribbon and click **MQTT Client**. The MQTT Client panel opens on the right side.
  </Step>
  <Step title="Enter broker settings">
    Fill in the connection fields:
    - **Host** — IP address or hostname of your MQTT broker (e.g., `192.168.1.100` or `broker.hivemq.com`)
    - **Port** — Default is `1883` for unencrypted connections, `8883` for TLS
    - **Client ID** — A unique identifier for this connection (auto-generated by default)
    - **Username / Password** — Leave blank if your broker does not require authentication
  </Step>
  <Step title="Connect">
    Click **Connect**. The status indicator turns green when the connection is established. If it fails, verify the broker address, port, and firewall rules.
  </Step>
</Steps>

## Map signals to topics

After connecting, you define signal mappings to link simulation signals with MQTT topics.

<Steps>
  <Step title="Add a publish mapping">
    Click **Add Publish**. Select the simulation component and signal you want to publish, then enter the MQTT topic to publish to (e.g., `vc/conveyor/speed`). Every time the signal value changes in the simulation, the new value is published to that topic.
  </Step>
  <Step title="Add a subscribe mapping">
    Click **Add Subscribe**. Enter the MQTT topic to subscribe to and select the simulation signal to update when a message arrives. Incoming message payloads are written directly to the mapped signal.
  </Step>
  <Step title="Test the mappings">
    Run the simulation. Use an MQTT client tool (e.g., MQTT Explorer or `mosquitto_sub`) to verify messages are being published, and publish test messages to verify subscriptions update simulation signals correctly.
  </Step>
</Steps>

## Payload format

The MQTT Client plugin sends and receives signal values as plain text:
- **Boolean signals** — `0` or `1`
- **Integer/Real signals** — numeric string, e.g., `42` or `3.14`
- **String signals** — raw string value

<Note>
  The plugin does not support JSON payloads natively. If your broker requires JSON, use a Python script to parse incoming payloads and set signal values manually.
</Note>

## Disconnect

Click **Disconnect** in the MQTT Client panel to close the connection cleanly. Mappings are saved with the layout and reconnected automatically when you reopen the layout and click **Connect** again.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Connection fails immediately">
    Check that the broker host and port are correct and reachable. Try pinging the broker host from your machine. Verify that no firewall is blocking the MQTT port.
  </Accordion>
  <Accordion title="Signals are not updating">
    Confirm the topic names match exactly — MQTT topics are case-sensitive. Check that the simulation is running (signals only change during simulation). Verify the subscribe mapping points to the correct component and signal.
  </Accordion>
  <Accordion title="Authentication error">
    Ensure the username and password match what is configured on the broker. Some brokers require a specific Client ID format — check the broker documentation.
  </Accordion>
</AccordionGroup>
