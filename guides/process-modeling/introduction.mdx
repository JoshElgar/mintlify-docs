---

Process Modeling is a simulation methodology in Visual Components that lets you model material flow and manufacturing processes using a dedicated set of eCatalog components. Rather than scripting custom behavior for every machine and conveyor, you define products, flows, transport links, and process statements that together describe how parts move through your factory. The simulation engine then orchestrates all movement automatically.

<Note>
Process Modeling is available in the **Professional** and **Premium** editions of Visual Components 5.0. Some specific components also work with Essentials.
</Note>

## Core concepts

Before building a layout, it helps to understand the five concepts that every Process Modeling simulation is built on.

<CardGroup cols={2}>
  <Card title="Products" icon="box">
    Products are the items that travel through the simulation. Each product is described by a **product type**, which defines its name, 3D geometry, and custom properties. A feeder introduces products into the layout at a configurable rate.
  </Card>
  <Card title="Flows" icon="arrow-right-arrow-left">
    A **flow** is an ordered sequence of process steps that a product type follows from start to finish. Flow groups contain one or more product types and define the overall route through the layout.
  </Card>
  <Card title="Transport links" icon="link">
    Transport links are directional connections between PM components. They define which paths a product can physically travel. Without a transport link between two components, no product can move between them.
  </Card>
  <Card title="Processes" icon="gear">
    Each station, machine, or conveyor section in the layout hosts one or more **processes**. A process describes what happens to a product when it arrives — waiting, machining, assembly — using a list of process statements.
  </Card>
  <Card title="Resources" icon="person-running">
    Resources are mobile entities — humans, mobile robots, or forklifts — that carry out tasks assigned by PM controllers. They move autonomously between processes and can load, unload, or assist with operations.
  </Card>
  <Card title="Layouts" icon="map">
    A **layout** is the complete 3D scene that contains all PM components, wired together with transport links and driven by a shared flow definition. You build layouts by dragging components from the eCatalog into the scene.
  </Card>
</CardGroup>

## eCatalog component families

Process Modeling components live in the **PM** folder of the eCatalog (in earlier versions this folder was called "Process"). The three main families are:

<AccordionGroup>
  <Accordion title="PM Feeders">
    Feeders introduce products into the layout. A **Source Feeder** generates products at a defined interval and sends them into the first process in the flow. You configure which product type it feeds and at what rate from the properties panel.
  </Accordion>
  <Accordion title="PM Stations">
    Stations represent individual process steps — machines, workbenches, buffers, sinks, and conveyor sections. Each station hosts a process executor that runs process statements during the simulation. You connect stations to each other using transport links.
  </Accordion>
  <Accordion title="PM Resources">
    Resources are mobile agents. You add them from the **PM Resources** sub-folder and configure their behavior through resource missions and controller settings. Resources respond to transport requests generated by process statements.
  </Accordion>
</AccordionGroup>

## How a simulation runs

When you press **Run**, the simulation follows this sequence for every product:

<Steps>
  <Step title="Products are created">
    The Source Feeder creates a product instance of the configured type and places it at the start of the flow.
  </Step>
  <Step title="Products follow the flow">
    The process flow defines the ordered list of stations the product must visit. At each station, the product waits for the process executor to complete its statements.
  </Step>
  <Step title="Transport moves products">
    When a process executor issues a Transport Out statement, the simulation looks for an available transport link or resource to carry the product to its next destination.
  </Step>
  <Step title="Processes execute statements">
    At each station, process statements run in order — delays, signal waits, attach/detach operations, or calls to robot routines.
  </Step>
  <Step title="Products are consumed">
    A Sink process at the end of the flow removes products from the simulation and records throughput statistics.
  </Step>
</Steps>
